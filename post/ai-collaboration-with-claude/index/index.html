Claude와 나눈 AI 협업 이야기

12월 22, 2025

요 몇 주간, 회사 프로젝트를 하면서 정말 많은 시간을 Claude Code를 사용해서 작업해 왔다.

그러면서 내가 지금까지 가지고 있었던 상식? 인식? 과 좀 많이 다르다는 느낌을 지속적으로 받았다. ‘어떨 때는 이렇게 쓰면 안되겠다.’ 또 어떨 때는 ‘이렇게 쓰는게 더 맞는거 같은데 그럼 일반적으로 이야기하는거랑 다른거 같은데?’ 같은 생각들…

집중적으로 작업하던 회사 프로젝트의 코어 부분에 대한 작업이 얼추 마무리 되면서, 지금까지의 내 느낌에 대해 Claude에게 묻고 싶어졌다.

그렇게 두서 없는 Claude와의 대화가 진행되었다.

대화가 끝나고, 이 대화를 어딘가에 기록으로 남겨야겠다고 생각했다. 이 내용은 Claude와 내가 나눴던 대화 내용을 기반으로 Claude가 정리한 결과물이다.

AI 도구(Claude)와의 코딩 협업에 대한 솔직한 대화.

속도와 품질의 트레이드오프, 실제 가치가 어디에 있는지, 그리고 효과적으로 협업하는 방법에 대한 논의.

대화 환경:

  • 모델: Claude Opus 4.5 (claude-opus-4-5-20251101)
  • 도구: Claude Code (Anthropic 공식 CLI)

목차

목차 이름을 클릭하면 상세 내용으로 이동한다.

1. AI 협업의 딜레마

  • 속도 vs 코드 품질 트레이드오프
  • 패턴 드리프트 문제
  • 검증 오버헤드의 딜레마
  • 유지보수의 현실
  • 도구와 작업자의 관계

2. 이해관계자 압박과 인식의 두려움

  • AI 도구의 유혹
  • “역행하는 사람"으로 보일까 봐 두려움
  • 프레이밍 전환 전략: “AI 쓰지 말자” → “AI를 더 잘 쓰자”
  • 장기적 관점
  • 현실적 대응

3. AI 시대의 아키텍처와 패턴

  • 기존 접근 vs AI 시대 접근
  • 비용 구조의 변화
  • 이너 아키텍처 vs 패턴/컨벤션
  • Clean Architecture / Hexagonal 도입 시점
  • 실용적 결론

4. 실용적 전략

  • AI가 잘 따라가지 못하는 영역
  • 효과적이었던 방법 (Exemplar, 명시적 규칙, 즉각 피드백)
  • 샘플 프로젝트 + 문서 전략
  • AI 컨텍스트도 유지보수 대상
  • 현실적 타협

5. AI의 실제 가치

  • 치밀한 유지보수가 필요한 프로젝트에서의 AI 활용
  • 아이러니: 가장 잘하는 게 가장 가치 있는 게 아님
  • 병목의 이동
  • 사고 파트너로서의 가치

6. 효과적인 “같이 생각하기”

  • 같이 생각하기의 가치
  • AI가 지침을 점점 안 따르는 이유
  • 효과적인 방법들 (도전 요청, 대안 요청, 역할 부여 등)
  • “말해야 생각한다” 현상
  • AI의 “생각"에 대한 진실

핵심 인사이트

  1. 도구는 작업자에게 맞춰야지, 작업자가 도구에 맞추면 안 된다

  2. 비용 구조가 바뀌었다: 코드 작성은 저렴해지고, 리팩토링은 상대적으로 비싸졌다

  3. AI의 실제 가치는 코드 생성 속도가 아니라 사고 파트너 역할

  4. AI 컨텍스트 관리도 프로젝트 유지보수의 일부

  5. AI는 출력하지 않으면 생각하지 않는다: 중요한 건 명시적으로 말하게 해야 함

  6. “AI 쓰지 말자"가 아니라 “AI를 더 잘 쓰자"로 프레이밍하라
